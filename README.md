# TOPBOX SUPPORT OS

> **Система контроля качества VPN-продукта и омниканальной техподдержки на 40 000 абонентов**  
> Интеграция с Telegram и Instagram, пул бесплатных моделей OpenRouter с авто-фоллбэком, 5 уровней ITSM-аналитики и 4-уровневая ролевая модель.

---

## 🎯 Главная концепция системы

При масштабе в 40 000 пользователей поддержка не может работать «по ощущениям». Поддержка становится **сенсором качества продукта**:
1. Каждое обращение классифицируется по единой таксономии (10 категорий + подкатегории).
2. Каждому обращению присваивается **Паспорт тикета** из 7 обязательных полей + техническая телеметрия.
3. Главная метрика — не абсолютное число обращений, а **доля от всей базы 40 000 пользователей** и показатель **User Problem Rate** (уникальные пользователи с технической проблемой / активная база).
4. Автоматический поиск системных аномалий (**Drill-down L5**: Платформа + Оператор + Приложение).
5. Ведение **Problem Register** и связь с **Product Backlog** (ITIL/ITSM): устранение первопричин экономит сотни часов поддержки.

## 📊 5 Уровней аналитики (Support Analytics System)

### Уровень 1. Обязательная классификация обращений
10 фиксированных категорий с подкатегориями:
- 🔴 **Не подключается**: приложение, ключ, сервер, оператор, устройство
- 🟠 **Медленно**: оператор, сервер, Wi-Fi, приложение
- 🟡 **Не работает конкретный сайт**: блокировка, DNS, маршрут, сайт
- 🔵 **Не умеет подключить**: инструкция, установка, настройка
- 🟣 **Проблема с приложением**: вылетает, не открывается, ошибка
- ⚫ **Ограничения оператора**: мобильная сеть, Wi-Fi, регион
- 💳 **Оплата**: оплата, продление, возврат
- 🔑 **Подписка**: ключ, тариф, срок, активация
- 🟢 **Всё исправлено**: проблема решена
- 🔴 **Не решено**: техническая проблема требует инженера

### Уровень 2. Паспорт обращения (7 обязательных полей)
1. `User ID`: ID абонента в VPN
2. `Устройство`: iPhone / Android / Windows / Mac / Linux / Роутер / Другое
3. `Оператор`: МТС / Мегафон / Билайн / Tele2 / Ростелеком / Wi-Fi / Другой
4. `Приложение`: Amnezia / Happ / v2rayNG / Outline / Shadowrocket / Karing / Другое
5. `Проблема`: симптом неполадки
6. `Причина`: root cause (блокировка ТСПУ, сбой сервера, ошибка DNS...)
7. `Результат`: итог решения (смена протокола, выдан новый ключ, передано инженеру...)
- *Дополнительно фиксируются:* время создания, время первого ответа (FRT), время решения (MTTR), помогла ли инструкция, повторное обращение, эскалация инженеру, критичность (P0, P1, P2, P3).

### Уровень 3. Метрики относительно всей базы (40 000 пользователей)
- 40 000 абонентов ➔ 92-95% работают штатно, ~5% имеют проблемы, ~2% неизвестный статус, ~1% неактивны.
- **User Problem Rate**: `Уникальные пользователи с проблемой / Активные пользователи` (защита от искажения метрик одним пользователем с 15 сообщениями).
- **Support Score**: FRT, MTTR, FCR (First Contact Resolution), Reopen Rate, CSAT, Automation Rate, Deflection Rate, Escalation Rate.

### Уровень 4. Рейтинг причин (ТОП проблем)
- Автоматический расчет ТОП-10 причин за день/неделю с % доли от общего числа и трендом динамики (+/- %).
- Генерация еженедельного отчета **«VPN — Support Weekly»** и 5-минутного ежедневного дайджеста для руководства.

### Уровень 5. Drill-Down аналитика и Problem Register
- Сквозное пересечение факторов (Платформа + Оператор + Приложение).
- Автодетект паттернов: например, `Android + МТС + Amnezia = 380 обращений` ➔ система подсвечивает критическую аномалию и предлагает занести её в **Problem Register**.
- **Product Backlog** формируется на основе реальных данных саппорта с расчетом предотвращенных обращений и сэкономленных часов.

## 🤖 OpenRouter AI & Пул бесплатных моделей

Система интегрирована с OpenRouter API и использует цепочку бесплатных моделей:
- `google/gemini-2.0-flash-exp:free`
- `meta-llama/llama-3.3-70b-instruct:free`
- `mistralai/mistral-small-24b-instruct-2501:free`
- `deepseek/deepseek-r1:free`
- `deepseek/deepseek-chat:free`
- `qwen/qwen-2.5-72b-instruct:free`

### Автоматический Failover
Если выбранная модель выдает статус **429 (Rate Limit)** или **503/500**, движок мгновенно и без прерывания запроса переключается на следующую бесплатную модель из пула. При отсутствии внешнего ключа включается встроенный эвристический парсер, поэтому система полностью работоспособна даже офлайн!

### 3 Режима работы ИИ
1. **AI Auto-Triage**: автоматическое определение устройства, оператора, приложения, категории и диагноза по тексту сообщения.
2. **AI Copilot**: генерация готового профессионального ответа на русском языке с учетом контекста тикета и базы знаний.
3. **AI Deflection / FAQ**: автоматические подсказки при стандартных сценариях (P3).

## 📱 Интеграция с Telegram и Instagram

### Telegram (@topvpnhelp_bot совместимый)
- Полная поддержка `aiogram 3`.
- Прием текста, фото, документов, голосовых.
- Создание персональных тем (Forum Topics) в супергруппе операторов.
- **Контроль графика работы**: с 09:00 до 20:00 МСК с кулдауном ночных уведомлений (один раз за ночь на абонента).
- **Автовыдача ключа по триггерам**: регулярные выражения («где ключ», «не пришла подписка», «мой ключ» и др.) с часовым антиспам-кулдауном.
- **Интерактивный визард самодиагностики**: кнопка «❌ Не работает VPN» ➔ выбор устройства, оператора, симптома и приложения ➔ моментальное формирование паспорта и выдача точечной рекомендации.

### Instagram Direct
- Вебхук Meta Graph API (`/api/webhooks/instagram`) с верификацией `hub.challenge`.
- Прием входящих сообщений в единую очередь обращений.
- Отправка ответов оператора обратно в директ через Meta Graph API.
- Встроенный симулятор для локального тестирования без боевых токенов Meta.

## 🔑 Управление ключами VPN (databasetop Adapter)

- Прямой адаптер к базе основного сервиса (PostgreSQL `databasetop` / локальное хранилище).
- Просмотр действующих ключей (протокол: Vless, ShadowSocks, Amnezia WG; сервер: NL-01, NL-03, DE-01; трафик, дата окончания).
- Кнопка **«Отправить ключ»**: отправка действующего ключа клиенту в 1 клик.
- Кнопка **«Пересоздать ключ (Reset Key)»**: криптографическая генерация новой конфигурации с маскировкой Reality и мгновенный отзыв скомпрометированного ключа.
- Кнопка **«Отправить инструкцию»**: выбор платформы (iOS, Android, Windows) и отправка пошагового руководства.

## 🚀 Быстрый старт и запуск

### Вариант 1. Запуск через Docker Compose (Рекомендуется для продакшена)

```bash
# 1. Склонируйте репозиторий и перейдите в папку
cd support-vpn

# 2. Скопируйте файл переменных окружения
cp .env.example .env

# 3. Запустите стек через Docker Compose
docker compose up -d --build

# Панель управления доступна по адресу:
# http://localhost:8080
```

### Вариант 2. Локальный запуск для разработки

#### 1. Бэкенд (Python 3.11+ / FastAPI):
```bash
# Создание виртуального окружения
python3 -m venv .venv
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Инициализация базы данных и сид-данных 40k
python -m app.seed

uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

#### 2. Фронтенд (React / Vite / Tailwind):
```bash
cd frontend
npm install
npm run build # для production сборки в frontend/dist

npm run dev   # для локальной разработки с HMR на порту 5173
```

## 🖥️ Развертывание на сервере из GitHub и работа с пушами

### Шаг 1. Генерация SSH-ключа на сервере (для безопасного pull и push без ввода пароля)
Подключитесь к вашему VPS-серверу по SSH:
```bash
# На сервере генерируем ED25519 ключ:
ssh-keygen -t ed25519 -C "server@support-platform"

# Выводим публичный ключ:
cat ~/.ssh/id_ed25519.pub
```
1. Скопируйте полученную строку.
2. В GitHub перейдите в **Settings ➔ SSH and GPG keys ➔ New SSH key** (или в настройки репозитория: **Settings ➔ Deploy keys ➔ Add deploy key** с галочкой *Allow write access*).

### Шаг 2. Клонирование репозитория на сервер
```bash
git clone git@github.com:yusuff84/support-platform.git /opt/support-platform
cd /opt/support-platform
```

### Шаг 3. Настройка окружения и запуск
```bash
# 1. Создайте файл конфигурации:
cp .env.example .env

# 2. Заполните боевые переменные (токен Telegram бота, OpenRouter, база VPN):
nano .env

# 3. Запустите стек в 1 команду через готовый скрипт:
./deploy.sh
# или через Docker Compose напрямую:
docker compose up -d --build
```

### Шаг 4. Настройка Git на сервере для отправки изменений (Git Push)
Чтобы коммитить и пушить правки прямо с сервера обратно в GitHub:
```bash
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"

# Проверка и пуш:
git add .
git commit -m "fix: server configuration update"
git push origin main
```
